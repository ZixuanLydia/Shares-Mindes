# Secret Garden

NYU ITP · Shared Minds 本地交互原型

本轮逐项状态、实际测试结果与剩余提交材料见 [Secret Garden V1 审核报告](<Secret Garden V1 Audit.md>)。

## 多人共享（同一 Wi-Fi）

1. 在这台电脑双击 **Start Shared Garden.command**。它会启动共享服务并自动打开花园，演示期间保持终端窗口开启。
2. 同一 Wi-Fi 的另一台电脑打开终端中 **Invite on this Wi-Fi** 后面的地址。两个人须使用同一个服务地址，不需要安装项目。
3. 继续使用 **Plant a Thought**，在原来的昵称栏填写自己的名字并种花。另一人的花会自动出现在花园里，通常约一至两秒同步；页面顶部的小字显示共享或等待补传状态。
4. **My Flowers** 只显示当前浏览器身份创建的花。**Timeline** 显示大家的作品与昵称。点花可查看作者、原文和时间，**Find Connections** 可以寻找其他人的相近想法，继续拖近、融合和分开。

在同一台电脑演示两个人时，可分别使用 Chrome 与另一个浏览器，或一个普通窗口和一个无痕窗口。两个普通标签通常共享同一个身份，不能用修改昵称来模拟两个人。身份保存在浏览器中，当前没有跨设备登录或账号恢复。

共享版将主动种下的想法保存到启动服务的电脑：`server/data/garden.sqlite3`，服务停止后作品仍在，下次启动继续恢复。原来的花朵 JSON、作者快照、创建时间和生长记录格式继续使用，服务器为每朵新花分配不冲突的位置。原来直接打开 HTML 的离线花园及其 `secret-garden:v1` 数据保留，既不自动迁移，也不自动发布到共享花园。

只有作者能保存自己花朵的位置和开放进度；大家都能欣赏别人的俯视绽放、回看与融合。融合和运镜是展示效果，不改写两个人的原作。断线时新花或位置调整会显示 **Waiting to share**，先保存在当前浏览器，重连后自动补传；确认收到后才显示已共享。收到的新花会在返回花园时柔和出现，避免打断当前镜头。

## 拖动花朵

- 在花园中按住花朵并拖动，可左右或上下重新摆放。拖动超过一小段距离才开始移动，轻点仍进入俯视。深度、颜色、花型和开放进度保持不变。
- 自己的花：松手保存位置；共享模式下，其他人的花园会同步看到新位置。刷新后仍保留。
- 别人的花：可暂时拖动欣赏，松手后柔和回到其保存的位置。中央大花可在本次预览中自由摆放。
- 想继续开花时，按住 **Shift** 再向上拖自己的花；选中后按上方向键也可以。Body 的张掌／握拳、种花预览滑杆继续使用。
- 在 **Find Connections** 内，原来的拖近融合与点击空白处分开继续保留。**Esc** 可取消正在进行的摆放；失去窗口焦点或调整窗口大小也会取消，不保存未完成的移动。

如果共享服务在更新前已经运行，请先在其终端按 **Control+C**，再双击启动器重开，以加载新增的位置同步接口。

共享服务是本机／局域网版本，没有部署到公网，也没有接入 Firebase、付费服务或修改云端权限。启动器依赖项目中的 `server` 目录，请保持当前项目结构。结束演示后在终端按 **Control+C** 停止服务。本机 `localhost` 的 Body 模式保持可用；同一 Wi-Fi 的普通 HTTP 地址在远端浏览器通常不能开启摄像头，仍可用鼠标完整操作，详见[浏览器摄像头的安全要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

## 本地演示

在 Finder 中双击 **Secret Garden.html**，可继续使用离线单人模式，建议用 Chrome 打开。背景与花园代码嵌在 HTML 里。请将 **body-assets** 和 **semantic-assets** 两个文件夹与 HTML 放在一起：前者用于摄像头追踪，后者用于本地句意匹配。离线模式不上传想法；摄像头画面在两种模式下都不上传。

英文排版统一使用 **Instrument Serif**（标题、想法展示）与 **DM Sans**（按钮、正文、属性和时间），字体已嵌入 HTML，打开时无需联网。中文分别使用系统宋体与苹方回退。字体许可同时保存在 HTML 和 `type-assets` 文件夹。当前以电脑端演示为准。

每次打开或刷新页面时，**Secret Garden** 与副标题都会缓缓出现，约三秒后淡出；提前点击或开始拖动会更快结束开场。开场动画不读写花朵记录，花园常态只保留左下角的简短操作提示。浏览器标签里的名字继续保留；减少动态效果模式会跳过开场动画。

- 点花园里的花，约两秒内会从斜侧移到接近 88° 的俯视。镜头上升时，花瓣逐渐盛开，想法、昵称、时间和关键词在旁边淡入。点 **Back to Garden** 或按 **Esc**，可沿路径返回。
- 在一朵已种下的花的俯视画面点 **Find Connections**。花园先比较原始想法的句意，最多四朵相关花从各自的位置聚到焦点周围；联系越强，花越靠近，光晕和光点流动也越明显。列表可以查看所有达到匹配门槛的作品。第一次查找会加载本机模型，期间仍可返回花园。
- 把一朵聚拢的小花拖到焦点花上。两朵花在相接时开始融合，花瓣交错成一朵双色玻璃花，暖光从相接的一侧沿瓣缘扩散。松手后，右侧用两条想法中的具体细节写出一句融合句，下方保留两条原文。点击花园里的空白处，花瓣先分开，小花再沿弧线回到聚拢时的位置。
- 轻点聚拢的花或列表项可平滑切换焦点，**Hide Connections** 收起关系。点 **Back to Garden** 或按 **Esc**，花朵会沿各自路径回到原位。位置和开放进度以原保存的记录为准。
- 点中间的大花体验俯视，返回后可使用 **Demo flower bloom** 演示控件。滑杆和 **Bud**、**Half-open**、**Bloom** 可控制开放程度，播放键可播放、暂停和继续。
- 在场景上移动鼠标，远处和近处的花以不同幅度移动。右上角 **Parallax** 可开关视差。点击场景空白处或按 **Esc** 可取消选中。
- 点 **Plant a Thought**，输入一句想法，也可以填昵称。下一步会出现预设联想词，以及花型和颜色的即时预览。以后种花时会自动带入上次使用的昵称。
- 点 **Grow flower**。向上拖动花朵或移动滑杆让花绽放，滑杆也支持方向键。按钮旁会显示将种成花苞、半开还是盛开。点 **Plant in Garden** 种下。
- 点 **My Flowers** 打开作品列表。切换到 **Timeline** 可按本地日期和创建时间从新到旧浏览。点一条记录会在花园里选中原花并打开详情，点 **Back** 回到刚才的列表或时间轴位置。
- 在花朵详情点 **Replay growth**，镜头靠近后会播放这朵花记录过的开放过程。花苞从斜侧观看，随开放程度逐渐升高。底部可暂停、重新播放或拖动进度，旁边显示对应记录的时间、输入方式和开放程度。点 **Back to Garden** 返回原花，再点详情里的 **Back** 回到列表或时间轴。
- 从俯视返回后，已种的花会处于选中状态，可以查看原文、昵称、创建时间、花型、颜色、尺寸、当前开放进度和联想词。普通拖动保存位置；按住 Shift 向上拖自己的花，松手保存新的开放进度。俯视运镜中的绽放是展示预览，返回会恢复此前的开放进度。也可在花朵或详情标题获得焦点时按上方向键。浏览器允许本地存储时，刷新后也能找回记录。

## Body 身体互动

1. 点右上角 **Body mode**，再点 **Enable camera** 并允许浏览器使用摄像头。镜像预览里的小光点表示手掌位置，花园里的对应光点表示手正在影响哪里。
2. 保持手在摄像头画面里，张开手掌让花展开，慢慢握拳让花合拢。手指张开一半时，花也会停在中间状态。开始时默认控制主花，把张开的手所对应的光点移到另一朵花附近即可换目标。握拳或把手稍微收回来时，会继续控制刚才的花。
3. 在 **Plant a Thought → Grow flower** 也能点 **Body mode** 开启摄像头，用张掌和握拳反复调整预览花的开放程度。种植时会保存当时的开放进度和双向开合记录。花园中已有花朵的身体互动是临时展示，可以继续按住 Shift 向上拖动自己的花来保存新的开放进度。
4. **Pause camera** 会释放摄像头，**Resume camera** 会重新开启，**Close** 会关闭面板并结束追踪。进入俯视、花朵详情、历史、输入与选型页面，或切换到其他标签时，摄像头会自动暂停。回来后可以手动恢复。

手部关键点由随附的 MediaPipe 模型在浏览器内计算。页面只请求视频，摄像头画面只用于即时预览和追踪，既不上传也不保存。若拒绝权限、摄像头不可用或组件加载失败，继续用原来的鼠标和键盘操作即可。

Body 模式会在支持的浏览器中把识别放到后台 Worker，每次只处理最新的一帧，避免积压旧画面。四根手指的关节弯曲和伸展比例映射到花朵开放程度，花园光点与预览标记共用平滑后的位置。短暂漏识别时先保持当前开合，持续失去追踪或暂停后，已有花朵会柔和恢复保存状态，Grow 草稿保留最后调整的进度。手部移动仍能让花轻摆，移过相邻花朵可触发少量光点传播。建议用 Chrome 打开同一份本地页面体验。

## 生长记录与回放

从本版本开始，Grow 中的鼠标、键盘和手部开花过程会随作品一起保存。种下后，按住 Shift 向上拖动自己的花，或按上方向键继续开放，也会追加实际发生的生长记录。普通摆放只更新位置，不添加生长记录。取消拖动会放弃本次记录。相隔很久的操作在回放时会压缩等待时间，让整段过程在约四至七秒内播放。

旧作品已有的开放程度会作为一个 **Saved state** 展示，时间显示为空。此前的生长过程无法从最终状态还原。之后继续打开旧花时，回放会从这个已知状态开始。尚未发生开放变化的花，会直接展示其已记录状态。

回放只改变当前展示，退出后恢复作品保存的开放程度。花园里的临时手部共鸣、普通俯视时的展开与花朵融合继续作为展示动画。

## 原型的实现

背景采用一张为原型生成的玻璃花园图，近处以同一张图的柔焦遮罩层参与视差。主花由带透视投影的双面曲面花瓣绘制，前后表面之间留出厚度，侧壁保留花瓣厚度，并沿边缘弯出圆弧。瓣面带有从根部向外展开的浅褶和细纹，花瓣开合或转动时，细纹会随曲面一起变化。接近盛开时，外圈花瓣会以不同弧度微微向上卷起。瓣面采样身后的花园，随视角轻微改变折射位置，暖色透光和边缘亮斑会跟随转动。开放进度持续改变花瓣角度、形态与遮挡顺序。种下的花复用同一套绘制，按深度排序，按需刷新视角。

## 俯视运镜

现有玻璃花使用程序生成的三维花瓣曲面。每片花瓣包含带厚度的前后表面、圆边和褶皱，由透视相机投影到 Canvas 2D。俯视时，相机绕同一朵花升高并缩短距离，花瓣、花心和高光在同一模型上连续重绘。现有杯形、外展形和高身花型共用这套几何，各自使用对应的构图范围。背景花园是静态图像和视差图层，聚焦时通过轻微位移和暗化退到背景。

背景素材使用内置图像生成工具制作，并嵌入 HTML。创作提示为黄昏的玻璃花园，粉橘、淡紫和浅蓝花朵，暖色散射光与层叠薄雾，画面中央留出空间给实时绘制的主花。

## 本地关系匹配

使用量化的多语言句向量模型 **paraphrase-multilingual-MiniLM-L12-v2**，每句想法转成 384 维向量，按余弦相似度排序。中文与英文可以相互比较，原来的预设联想词不参与语义排名。当前原型使用 0.34 作为匹配门槛，相似度是句子表示的接近程度，不是准确率或概率。模型文件、分词器和运行组件均放在 `semantic-assets`，约 110 MB，按需加载；模型在后台 Worker 中运行，以免阻塞花园动画。逐句计算保证同一句不因批次不同而改变结果。

句向量以模型版本和规范化文字为键保存在 IndexedDB，存储不可用时改用本次会话的内存缓存。刷新后，已计算过的文字可以直接复用向量。花朵 JSON 与 `secret-garden:v1` 的结构保持兼容，向量作为可重新计算的索引分开保存。以后可将 `GardenSemantic.embed(texts)` 换成服务器接口，而不改变花朵或交互的数据格式。

关系文案与融合句继续采用本地语言规则，结合两条原文的具体细节进行组合；它不是生成式大模型写作。右侧始终保留两条原文。`Shared threads` 只显示两条原文中都有依据的主题；模型发现关联而小型文案规则无法解释时，不编造共同关键词。模型加载失败时明确提示，并退回原来的共同关键词匹配；可以收起后重试。

聚拢位置、关系强度、融合与切换都属于临时展示状态；返回后每朵花恢复原来的位置和开放进度。已验证中文家庭晚饭回忆与英文 family dinner 的跨语言关联，以及预设标签相同但句意无关的作品不会被强行聚在一起。

模型与运行库来源、版本和许可证见 `semantic-assets/NOTICE.txt`。[模型说明](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2)、[Transformers.js 本地模型文档](https://huggingface.co/docs/transformers.js/custom_usage)。

## 花朵数据

花园将每朵花作为独立的 JSON 对象保存。浏览器本地存储键仍为 `secret-garden:v1`，包含作品数组和本机昵称设置。`author.id` 是本机作者 ID，`author.name` 记录该作品创建时的昵称。未填写昵称的作品显示 **Local gardener**。`size` 是相对示范花的比例，`openness` 为 0 到 1。位置的 `x`、`y` 为相对画面坐标，`z` 为深度。`createdAt` 保存为 ISO 时间，时间轴按浏览器的本地日期分组。`growth` 保存实际生长采样，每个采样有独立 ID、时间、开放程度和输入来源。读取旧作品时会兼容缺少 `growth` 的数据。

```json
{
  "id": "flower-id",
  "author": { "id": "local-author-id", "name": "Jun" },
  "thought": "我想把下雨的声音种在花园里。",
  "associations": ["Stillness", "Movement", "Reflection"],
  "appearance": { "form": "cup", "color": "peach", "size": 0.39, "openness": 0.65 },
  "position": { "x": 0.82, "y": 0.61, "z": 0.43 },
  "createdAt": "2026-11-11T05:00:00.000Z",
  "growth": [
    { "id": "growth-start", "at": "2026-11-11T04:59:55.000Z", "openness": 0, "source": "seed" },
    { "id": "growth-mouse", "at": "2026-11-11T04:59:58.000Z", "openness": 0.65, "source": "mouse" },
    { "id": "growth-planted", "at": "2026-11-11T05:00:00.000Z", "openness": 0.65, "source": "planted" }
  ]
}
```

如果浏览器限制本地文件的存储，页面会提示花只保留在本次访问。也可以用电脑上的本地服务器预览，在 HTML 所在文件夹运行 `python3 -m http.server 8000 --bind 127.0.0.1`，然后在浏览器打开 `http://127.0.0.1:8000/Secret%20Garden.html`。本地文件与本地服务器分别使用各自的浏览器存储。

## 后续同步接口

页面通过 `GardenData` 读写作品。界面和花园绘制使用同一份作品记录，并按 `id` 重新打开。

| 接口 | 用途 |
| --- | --- |
| `load()` | 读取本地作品集合。 |
| `createFlower(draft)` | 生成作品对象、唯一 ID 和创建时间，保存创建时的昵称。 |
| `save(flowers)` | 合并并保存作品，返回本地写入是否成功。 |
| `saveBloom(id, openness, { source, growth })` | 按作品 ID 合并并保存实际增长，返回完整作品、实际进度和本地写入结果。 |
| `growthPoint(openness, source, at)` / `growthFor(record)` | 创建采样，以及读取兼容旧作品的生长记录。 |
| `getNickname()` / `setNickname(name)` | 读取和更新本机的默认昵称。 |

共享模式通过 `GardenShared` 异步接口列出作品、创建作品和按 ID 保存开放进度与位置。匿名会话由服务端颁发，作者 ID 和写入权限由服务端验证，昵称按每朵花创建时保存。浏览器使用独立的 `secret-garden:shared:v1` 缓存与补传队列；服务器保存权威副本。移动通过独立的 `PATCH /api/flowers/:id/position` 更新，仅作者可写，保留原文、花型、开放程度和时间。未来可替换为 Firebase 等云端适配器，继续沿用作品 ID、作者快照和 JSON 格式。
